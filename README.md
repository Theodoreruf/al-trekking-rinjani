# Al-Trekking Rinjani website

Static website for the Al-Trekking Rinjani trekking agency (Mount Rinjani, Lombok).
The pages are generated by a small Python script, so all text is written once in a single file. The result is plain HTML/CSS/JS that can be hosted anywhere.

## Requirements

- Python 3.8+ (standard library only, nothing to install)
- A web browser

## How to run

```bash
# 1. Generate the pages into site/
python3 build.py

# 2a. Open directly in a browser
xdg-open site/index.html        # Linux
open site/index.html            # macOS

# 2b. Or serve locally (closer to real hosting)
python3 -m http.server 8000 --directory site
# then visit http://localhost:8000

# 2c. Or build and serve on your local network (phone, tablet, other PC)
python3 build.py --serve          # port 8000
python3 build.py --serve 8005     # custom port
```

`--serve` prints two addresses: `http://localhost:PORT` for this computer and `http://<your-LAN-IP>:PORT` for other devices on the same Wi-Fi or router. Open the second one on your phone. If it doesn't load, your firewall may be blocking the port. With ufw, run `sudo ufw allow 8000/tcp`. Stop the server with Ctrl+C.

Run `python3 build.py` again after every change to `content.py` or `build.py`.

## Architecture

```
.
├── content.py          # DATA: every piece of editable text
├── build.py            # GENERATOR: HTML templates, writes site/
└── site/               # OUTPUT: the deployable website
    ├── index.html                  (generated)
    ├── contact.html                (generated)
    ├── treks/<slug>.html           (generated, one per trek)
    └── assets/                     (hand-written, not generated)
        ├── css/style.css
        ├── js/main.js
        └── img/                    (logo.svg + your photos)
```

How the pieces fit together:

```
content.py ──imports──> build.py ──writes──> site/*.html ──link to──> site/assets/
```

### `content.py`: the data

Plain Python constants and nothing else. This is the only file you need to touch for content changes.

| Constant   | Used for |
|------------|----------|
| `AGENCY`   | Name, tagline, WhatsApp number, email, address, social links |
| `WHY_US`   | The three "why choose us" boxes on the home page |
| `INCLUDED` / `EXCLUDED` | Inclusion lists (home page and every trek page) |
| `PACKING`  | "What to bring" list on the home page |
| `FAQ`      | Question/answer pairs (home page and every trek page) |
| `TREKS`    | One dict per trek. Each dict generates one trek page and one card |

Fields of a trek dict: `slug` (file name and URL), `title`, `short` (card text), `duration`, `days`, `grade`, `distance`, `max_alt`, `start`, `price_from`, `image` (path relative to `site/`), `overview` (list of paragraphs), `highlights` (list), `itinerary` (list of `(heading, text)` tuples).

### `build.py`: the generator

HTML templates written as Python f-strings, with no templating library. All text is escaped with `html.escape`.

- `page(title, body, root)`: shared layout (header, menu, footer, WhatsApp button, CSS/JS links). `root` is the relative path prefix (`""` for top-level pages, `"../"` for `treks/`), so the site works from any folder or straight from the file system.
- Shared pieces: `trek_card()`, `enquiry_form()`, `faq_html()`, `ul()`, `wa_link()`.
- One function per page type: `build_home()`, `build_trek(t)`, `build_contact()`.
- `main()` writes every page into `site/`.

To **add a page**, write a `build_xxx()` function that returns `page(...)`, call it in `main()`, and add a menu link in `page()`.

### `site/assets/`: the front end (edited by hand)

- **`css/style.css`**: a single stylesheet. Colours, fonts and the corner radius are CSS variables in `:root` at the top, so the brand can be changed there. The palette is dark forest green (`--forest`, `--forest-2`) with stone grays (`--accent`, `--mist` for light backgrounds, `--on-dark` for gray text on green). On narrow screens (below 900px and 520px) the layout drops to one column.
  Images are passed in through a `--img` CSS variable and layered over a gradient, so a missing photo shows a coloured background instead of a broken image.
- **`js/main.js`**: plain JavaScript with no dependencies:
  - opens and closes the mobile menu
  - fills in the year in the footer
  - **enquiry forms**: on submit, it builds a WhatsApp message from the form fields and opens `wa.me` (the number comes from `window.AGENCY_WA`, which `build.py` adds to each page). No backend is needed.
  - highlights the current section in the menu bar on trek pages (`IntersectionObserver`)

### Images

Put your photos in `site/assets/img/` with these names:
`hero.jpg`, `custom.jpg`, `summit.jpg`, `crater-rim.jpg`, `lake.jpg`, `full.jpg`.
Landscape photos about 1600px wide work best. To use other names, change the `image` field in `content.py`.

## Common tasks

| Task | Where |
|------|-------|
| Change phone number / email | `AGENCY` in `content.py` |
| Set prices | `price_from` of each trek in `content.py` |
| Add a trek | Append a dict to `TREKS` in `content.py`, then rebuild. The card, page, menu and footer links are created automatically |
| Change logo / favicon | `site/assets/img/logo.svg` (used in header, footer and browser tab) |
| Change colours / fonts | `:root` variables in `site/assets/css/style.css` |
| Change layout of a page | The matching `build_*()` function in `build.py` |

> Do not edit the generated `.html` files by hand. The next build overwrites them.

## Deployment

Upload the contents of `site/` to any static host (Netlify, Vercel, GitHub Pages, Cloudflare Pages or ordinary shared hosting over FTP). The site needs no server-side code.

## Deployment (Vercel)

The site is deployed on Vercel from the GitHub repository. `vercel.json` tells Vercel to run `python3 build.py` and publish the `site/` folder, so every push to `main` rebuilds and redeploys the site automatically.

To publish a change: edit `content.py` (or `build.py`), then `git commit` and `git push`.
